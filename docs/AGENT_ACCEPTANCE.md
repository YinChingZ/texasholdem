## 覆盖的行为

- 一座位一份有效授权；服务端只存摘要；私有底牌与网页一致，其他玩家的当前底牌和浏览器恢复令牌不可见。
- 撤销授权后拒绝旧行动和旧收据查询；重复请求不重复下注，冲突请求、过期轮次和旧控制版本被拒绝。
- 关掉网页后 Agent 保持参赛；活跃期限结束后显示离线，恢复请求可继续。等待请求支持取消、单连接限制和撤销清理。
- 45／120 秒开局前设置，开局后锁定；恢复与接管不延长截止时间。
- 合法加注目标、全押跟注、短全押、再加注权及短开注补足；原有筹码守恒／边池回归通过。
- 手机视口验证凭证不写入 localStorage / sessionStorage；生成授权、实际 HTTP 连接、刷新保留底牌、关闭另一页面代打、人工接管和结算均通过。
- 共享 Schema 与 OpenAPI 一致；MCP 返回值经过输出 Schema 校验。

## 实机验证说明

首次 Codex 验收已发现工具，但非交互 CLI 默认 approval=never 导致连接工具不能执行。随后通过仅本次会话配置，为六个已授权的牌桌工具设置 approval_mode=approve；没有修改用户全局配置。第二次完成 3 个不同 lastResult.handId，并调用 release_control 成功。

验收程序 `agent/verify-codex.mjs` 可复现这一流程；需本机已登录 Codex，调用实际模型会产生正常用量。MCP/Python 20 手测试采用过牌／弃牌策略，证明连接、授权和状态推进，不评价扑克策略强弱。

未验证每一种第三方 harness、生产代理或公网部署；本次不做负载测试。功能默认关闭，仍需部署者配置 HTTPS/API 地址并显式开启 `AGENT_ENABLED=true`。
